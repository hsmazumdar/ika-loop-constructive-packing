## 1. Question and claim structure

General loop: **information -> knowledge -> application of knowledge to generate more (better/new) information -> loop.**
A learner turns experience into compact reusable knowledge, uses that knowledge to act and gather better or new
information, consolidates, and repeats. Packing (Expt 21-22) is ONE case study. The paper's claim is about the loop, tested
in several unrelated domains; it is NOT a claim about packing.

Four effects must each be shown (or reported as absent) in every case study; these are the pre-specified endpoints:

| id | effect | contrast (everything else identical, incl. number of experiences and number of learner updates) |
|---|---|---|
| E1 | knowledge-guided generation matters | `guided` vs `random` data generation |
| E2 | consolidation matters | consolidation on vs off (online-only update) |
| E3 | knowledge transfers | score on HELD-OUT tasks (unseen sizes / pieces / equations / compositions) |
| E4 | the loop improves across iterations | held-out score and generated-data quality vs iteration (round r store generates round r+1 data) |

E1 x E2 is a 2x2 factorial (guided/random x consolidate/no); the interaction (does guidance need consolidation?) is reported.
A supplementary **data-swap test** isolates data quality from learner state: a FRESH learner is trained on a frozen dataset of N
experiences generated by (a) the round-r store (guided) or (b) the random generator, with identical learner and update count;
held-out score of the two fresh learners is compared. This shows that guided generation produces better information, not only
that the store happens to be better.

## 2. Domain-agnostic loop and interfaces (implemented: `src/loop.py`, tested on a toy domain)

- `Domain` = information source. `sample_task(split, rng, index)`, `act(task, store, mode, rng, tau, eps) -> Experience`
  (one unit of information gathering: an episode, a batch of candidate expressions, a search, a candidate-program batch),
  `reference_score(task)` (normaliser only; never passed to a learner).
- `KnowledgeStore` = compact reusable knowledge. `observe(experience)` (fast / short-term memory), `consolidate()` (slow store:
  replay, simulated continuations, slow-weight averaging, concept/library promotion), `freeze()` (evaluation copy = the consolidated store only).
- Generator = `Domain.act` with `mode='guided'` (actions drawn from the store's scores, temperature/epsilon schedule) or `mode='random'`
  (actions drawn uniformly from the domain's action set). The store never contains a decision rule; the action set (grammar, legal moves,
  placements) is part of the domain, not of the learner.
- `run_loop` (the single driver, identical for all domains): sample TRAIN task -> generate -> observe -> every `sleep_every` experiences
  consolidate (if on) -> at checkpoints evaluate the frozen store on held-out tasks (near-greedy, no learning). Costs (episodes,
  expansions, evaluations) are logged per experience so that comparisons can be made at equal information cost.
- Compute matching: all arms get the same number of experiences, the same number of gradient updates per experience and the same
  consolidation schedule; only the factor under test differs. Random-generation arms still learn (from random data).

Knowledge store instances (all use a generic MLP/DeepSets value or policy model + optional library; none embeds a hand rule):
packing = afterstate value net + slow EMA net + concept library; puzzles = learned cost-to-go net; programs = guide net + learned subprogram
library; equations = expression-token policy net + subtree library.

## 3. Case study 1 - packing across problems

### 3.1 Problem generator (implemented: `src/polyomino.py`, `src/env.py`, `src/generator.py`)
- Piece pool: all one-sided polyominoes (rotations only, as in Expt 01) of size 3-7: 283 pieces (2, 7, 18, 60, 196 of sizes 3..7).
  The 16 pieces A-P of Expt 01-22 are a subset (`legacy` problem, 3,636 placements, matches Expt 01).
- A problem = board H x W, obstacle cells (the per-problem handicap), a catalogue of k pieces (k in 6..16, exactly one "large" piece of
  6-7 cells so that piece choice matters), piece budget (14 in the primary condition; none in the uncapped condition).
  The agent chooses piece and placement each step; unlimited supply; natural placing (contact > 0) by default.
- Splits (deterministic from (split, index)): `train` (8 board sizes 8x8..11x11 incl. rectangles; catalogues from the 224 TRAIN pieces only),
  `test_iid` (new problems, same sizes and pieces), `test_size` (7 UNSEEN sizes: 7x7, 12x12, 7x10, 10x7, 12x9, 9x12, 7x12),
  `test_piece` (>= 2 of 59 HELD-OUT pieces per catalogue, seen sizes), `test_both` (unseen sizes and held-out pieces), `legacy` (10x10, A-P),
  and `dev` (pilot/hyper-parameter selection only, never reported). Disjointness is unit-tested (0 spec-hash overlaps with train; 0 held-out
  pieces in any train catalogue; unseen sizes absent from train).
- Reporting set: 50 problems per test split (indices 0..49), fixed now; dev indices 0..49 of `dev`; train problems are drawn on the fly
  (indices from a seeded stream, never overlapping the 0..49 test indices because the splits use disjoint seed ranges).
- Hard variant (secondary, pre-declared because the standard variant leaves little room above the hand rule, see section 9): obstacle
  fraction up to 25% of cells and k in 4..7; its own train/test splits drawn with the same seeds scheme.
- Conditions (2x2): {capped 14, uncapped} x {natural placing, any legal placement}. Primary = capped + natural. Normalised score uses S1 = filled
  non-obstacle cells; uncapped S1 can reach the free-cell count, so scores are always normalised per problem.

### 3.2 Making the learner problem-agnostic without hand rules
The Expt 22 learner is tied to the 10x10 board, the A-P one-hot and 29 hand-chosen board counts. For Expt 23 the afterstate encoding becomes
translation-invariant and catalogue-independent:
1. **Local patch (primary encoding, no hand-designed quantity):** a 9x9 window centred on the placed piece's centroid (after canonical rotation
   of the piece), 3 binary channels (occupied by earlier pieces, outside-board-or-obstacle, cells of the new piece) = 243 raw inputs.
2. **Piece descriptors:** area, bounding box w/h, number of distinct orientations, normalised pool-index embedding replaced by shape moments
   (second moments of the cell set) so unseen held-out pieces are described by shape, not by an identity column.
3. **Global context (raw):** filled fraction, free cells left / area of the largest piece in the catalogue, pieces left in budget (or 1 if uncapped),
   board H and W normalised.
4. Optional **secondary variant "+counts"**: appends the Expt 22 counts (contact, new 1-cell holes, notches). Reported as a labelled variant; the
   primary result must hold without it (R1).
5. Same learning machinery as Expt 22 (afterstate value MLP with Monte Carlo returns (lambda = 1), fast net, STM, sleep every 200 episodes with
   prioritised replay, dreams, slow EMA net, concept library, meta-controller). Concept keys = (pool piece id, orientation, ring occupancy bits) are
   catalogue-independent. Capacity growth is OFF (it was never shown to help); meta-controller is ON in the full learner and OFF in an ablation.
6. Hyper-parameters are fixed from Expt 22 and checked once on `dev` only; no tuning on any test split.

### 3.3 Arms (packing)
Reference (not learners): uniform natural; hand rule; CEM-tuned hand rule (4 weights tuned on TRAIN problems by cross-entropy method, evaluated
on test splits - answers "were the hand-rule weights tuned?"); beam search; hand-rollout beam search (stronger reference).
Learners: **F** full (guided + consolidate); **R** random-data + consolidate; **N** guided, no consolidation (online-only = plain afterstate-MC);
**RN** random-data, no consolidation; **no-meta/no-dream/no-concepts** ablations (primary condition only, informational);
**DQN** and **PPO** generic baselines: same observation encoding, MLP, standard 1-step TD with target net and replay (DQN), clipped-ratio PPO with
a masked softmax over the candidate set; same number of environment episodes. Optional raw-board CNN DQN if torch is installed.
Streams per arm: 8 in the primary condition, 6 in the other three conditions (arms F, R, N, DQN only there).

### 3.4 Metrics
- Per problem: `score = S1 / ref`, ref = max(beam64, hand-rollout beam, mean hand-rule S1 over 60 episodes), computed once per problem and frozen
  (not clipped; values above 1 are possible and reported). Raw S1 is always reported alongside.
- Headline (E3/E4): mean normalised score over the union of the four test splits (equal weight per split) vs training episodes (checkpoints 0, 1k, 2k,
  5k, 10k, 20k), zero-shot (frozen store). Per-split curves are secondary.
- Few-shot: after training, the store continues the loop for K = 0, 10, 50 episodes on a single held-out problem; score on that problem (3 reps).
- Loop diagnostics (E4): mean normalised outcome of generated training experiences per round of 1,000; diversity of generated data (distinct
  final boards per 1,000); data-swap test (section 1).
- Headroom check (pre-declared "room" criterion): on test splits uniform/ref and hand/ref must leave visible room; if hand/ref >= 0.95 the hard
  variant becomes co-primary (see section 9 for what is measured).

## 4. Further case studies (very different kinds; each cheap on this PC)
All three reuse `src/loop.py`; each has train/held-out task splits, a reference solver, generic-NN baselines and the same four effects.

**CS2 - list-program synthesis (sequence/program task; recommended).** Task = input/output examples of a hidden composition of 2-6 primitives
from a small integer-list DSL (map +k / *k, filter by threshold, sort, reverse, take/drop k, cumulative sum, ...). Information = candidate programs run
on the examples (solved if all examples match). Knowledge = guide net (primitive-choice policy given a raw-example encoding) + library of promoted
reusable subprograms (compression is the "compact knowledge"). Guided generation = guide-sampled candidate programs within a fixed budget; random
= uniform candidates. Held-out = unseen compositions, longer depth, unseen constants. Reference = size-ordered enumeration (budget-matched).
Metric = fraction of held-out tasks solved within N = 2,000 candidates; solved-at-budget curves. Pure Python, about 0.05-0.2 s/task.

**CS3 - sliding-tile puzzles (grid/puzzle task).** Task = solve a scrambled n x m tile puzzle (2x3, 3x3, 3x4 train; 2x4, 4x4 etc. unseen). Information =
searches (solved/failed, expansion traces; labels = path cost found). Knowledge = learned cost-to-go net on a permutation-invariant tile encoding
(DeepSets over per-tile displacement and local neighbourhood; no Manhattan sum is given). Guided generation = best-first search under the net
(labels from its own solutions); random = random-walk scrambles with depth labels. Held-out = unseen sizes and deeper scrambles. Reference = A*
with Manhattan heuristic (reference only) under the same expansion budget. Metric = fraction solved within an expansion budget and mean solution
length / optimal on 3x3 and 2x4 (optimal available). Cheap: 3x3/2x4 are instant, 4x4 uses a node budget.

**CS4 - equation discovery / symbolic regression (optional third).** Task = recover a hidden y = f(x1, x2) from 30 samples; f drawn from a
grammar (unary/binary ops, constants) with depth <= 4. Information = candidate expressions scored by fit. Knowledge = token policy net conditioned on a
raw data encoding + library of reusable subtrees. Held-out = unseen operator combinations and an unseen variable count. Reference = brute-force
enumeration by size and a genetic-programming run under the same evaluation budget. Metric = fraction of held-out equations recovered (R2 > 0.999)
within a fixed evaluation budget. Slightly more costly than CS2/CS3 (estimate in section 7).

Recommendation: CS2 and CS3 are the minimum for a cross-domain claim; CS4 is added if time permits. Packing + CS2 + CS3 is a defensible NCAA scope.

## 6. Statistical plan (pre-specified; all analyses at the stream level)
- Unit = independent training stream. Per-stream value = mean normalised score over the reporting set at a checkpoint (headline: the final
  checkpoint, 20k episodes for packing; domain-specific budget in CS2-4). Test problems are fixed; a second analysis resamples problems
  (hierarchical bootstrap: streams, then problems) to support the claim about the problem distribution.
- Primary tests: F vs R (E1), F vs N (E2), F vs DQN, F vs PPO, each by **Welch t** (Satterthwaite df), one family per domain and condition:
  {F-R, F-N, F-RN, F-DQN, F-PPO, F-hand/CEM-hand (one-sample on per-stream means)} = 6 comparisons, **Holm** across the family.
  Sensitivity: exact permutation test and Mann-Whitney U (also Holm-adjusted); a result is called supported only if Welch-Holm holds AND both
  sensitivities have Holm-adjusted p < 0.10; otherwise it is reported as "survives Welch only".
- E4: paired (within-stream) bootstrap of score change between checkpoints and a stream-level slope; no plateau claims.
- Interaction E1xE2: difference-in-differences with a bootstrap over streams.
- Report per-stream values (dots), mean with 95% bootstrap CI, **median and IQM** across streams, and effect sizes (cells / normalised units).
- Transfer (E3): normalised score on each held-out split relative to `test_iid` (generalisation gap), with per-split CIs.
- Exploratory (labelled): ablations no-meta/no-dream/no-concepts, +counts variant, hard variant, few-shot.
- Seeds: training seeds 1000+ (disjoint from Expt 22 seeds and from every evaluation seed); streams per arm as in 3.3.
- No analysis choice (checkpoints, split weights, ref definition, tests, family) may change after the first main run; amendments are listed in section 12.

## 8. Reproducibility rules

## 9. Measured headroom of the references (pilot checks, Vivobook, 2026-10-01; `results/`)
Standard variant, capped, natural placing; 30 problems per split, 60 episodes for uniform/hand, beam width 64 (`run_beam`, mean 0.45 s per problem,
max 0.93 s). Normalised by max(beam64, hand mean):

| split | uniform/ref | hand/ref | share of problems with hand/ref < 0.90 |
|---|---|---|---|
| train | 0.765 | 0.950 | 0.10 |
| test_iid | 0.762 | 0.952 | 0.03 |
| test_size | 0.784 | 0.946 | 0.07 |
| test_piece | 0.772 | 0.943 | 0.07 |
| test_both | 0.775 | 0.949 | 0.13 |

Reading: uniform is about 24% below the reference, so the memory has room to matter against uniform and random-data arms (E1, E2 and the
DQN/PPO baselines). The hand rule is only about 5% below the reference, i.e. on the standard variant a learner can gain at most a few percent over it
(on the legacy problem the Expt 22d learner reached 91.76 vs hand 89.62 vs beam about 92-93). The beam reference is not an upper bound: on
`test_size_00001` the hand-rollout beam found 96 against 90 for beam64 and 86.8 for the hand rule. Hard variants leave more room
(hand/ref on 20 train problems: 0.939 at 6% obstacles, 0.932 at 15%, 0.925 at 25%; 0.898 and 0.894 with k in 4..7; share below 0.90 rises to
0.35-0.50), hence the hard variant is pre-declared. Uncapped legacy has more room still (uniform 78.97, hand 93.42, beam64 99). The cap and
natural placing change the reference numbers little on small boards (natural vs any-legal: uniform within 0.5, hand within 0.4); the cap can bind on
about 25-54% of standard problems (cap 14 x largest piece < free cells). Standard-variant headline claims should therefore be framed
against uniform/random-generation/DQN/PPO, and against the hand rule only on the hard variant.

## 10. Risks
(1) Patch-only encoding may learn slower than the Expt 22 counts; mitigation = +counts labelled variant, longer budget; (2) hand rule near the
ceiling compresses gains - hard variant; (3) DQN/PPO with large variable action sets can be unstable, so tuning on dev is allowed for baselines
(same budget as the learner's pilots) and reported; (4) the beam reference is weak on some problems - hand-rollout beam and frozen max-ref;
(5) one machine, one author - state it; (6) CS2-CS4 designs are untested and may need a redesign if headroom is absent (the same headroom table is
required for each before main runs).

iteration; 2x2 factorial; generalisation gap per split; data-swap), a manuscript section set for NCAA.

### Amendment A2 - 2026-10-01 23:10 IST (before any learner run)
Implementation details fixed while building the problem-agnostic learner (no run had been made):
- Encoding: the 9x9 patch is centred on the piece centroid in the board frame; the piece is NOT rotated to a canonical frame (its orientation is
  visible in the piece channel). D = 256 (243 patch + 6 shape descriptors + 3 dynamic globals + 3 static globals + obstacle fraction). No contact/hole/notch counts.
  The "+counts" variant is not built on the baseline day.
- Target: y = (S1 / free_cells - 0.7) / 0.15 (normalised by the problem's free cells, so returns are comparable across problems). Softmax temperature is
  expressed in S1 cells per 100-cell board (tau_eval 0.25 as in Expt 22). Hidden width 128, no capacity growth.
- N (plain afterstate-MC): online update only, 1 Adam step per episode at lr 5e-4, tau 2.0 -> 0.25 and eps 0.10 -> 0.01 linearly over the first 5,000 episodes.
- DQN (torch, afterstate Q on the same 256-d encoding, MLP 256-128-128-1): replay of 6,000 transitions, 4 updates of batch 64 per episode, lr 5e-4, terminal reward = y,
  gamma 1, hard target-network sync every 500 episodes; the next-state max is taken over a stored subset of 32 next candidates (24 best by the acting net + 8 random)
  - an approximation required to keep memory bounded; same exploration schedule as N.
- PPO (torch): policy = shared MLP scoring each candidate (masked softmax over the candidate set), critic = MLP on [global features, mean of candidate features];
  16 episodes per update, 4 epochs, clip 0.2, entropy 0.01, advantage = y - V(s_t) (terminal-only reward, gamma 1), lr 3e-4. Evaluation uses a softmax at the
  same tau_eval (0.25 cell-units) over the policy logits scaled to the same units is NOT possible, so PPO is evaluated by the argmax of its logits with
  probability-sampling at temperature 1 on the logits (recorded as 'greedy' and 'sample' scores; 'sample' is the one reported as main).
- Evaluation protocol as in A1 (50 problems per split x 3 reps, checkpoints 0, 1k, 2k, 5k, 10k, 20k). Raw S1 per (problem, rep) is stored; normalisation uses the frozen
  refs CSVs at analysis time.
- Stream length: 20,000 episodes in the two primary conditions (std and hard, capped_nat); 10,000 in the three other std conditions (decided from timing; recorded here).

### Amendment A5 - 2026-10-02 11:00 IST (before the matched arm or any tuning was run)
Compute-matched plain learner "NM" (isolates "more gradient work" from "replay + slow net + dreams + concepts").
- F per 200 episodes performs: 200 online Adam steps (one per episode, lr 5e-4, rows = that episode's afterstates) + one sleep of 40 Adam steps with batch 256 rows (lr 1e-3)
  = 240 Adam steps and about 200 x 13.25 + 40 x 256 = 12.9k gradient rows (std; episodes have 13.25 afterstates on average, hard 11.25).
- NM = N (guided, same acting, same anneal) + EXTRA online Adam steps on the SAME episode's rows only (no buffer, no replay, no slow net, no dreams, no concepts, no meta).
  Mode "rows" (primary, arm name NM): per episode a row credit of 40*256/200 = 51.2 is added; extra steps (lr 5e-4, as N's online step) are taken while credit >= rows of the episode.
  Gradient rows per 200 episodes then equal F's within one episode's rows; Adam steps per episode are about 4.9, more than F's 1.2 (reported, not matched).
  Mode "steps" (arm NMs, optional): credit 40/200 = 0.2 extra step per episode; matches F's Adam-step count (1.2/episode), rows about 1.2 episodes' worth.
- Verified by unit tests (`tests/test_matched.py`) before running. Not run until baselines finish. Added to the E-stream list as a 4th arm (F, R, RN, NM), 8 seeds x std and hard, 20,000 episodes.
- E1-E4 statistics family (analysis script `analyze_e.py`) gains the contrast F vs NM (matched compute; Holm family grows from 7 to 8 comparisons per condition).
